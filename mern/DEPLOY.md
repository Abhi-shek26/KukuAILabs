# Deploying Promo Finder (MERN)

Three moving parts, two of them free:

```
browser ──► Render web service (Docker image)          MongoDB Atlas M0 (free)
              Express API + built React app
              └─ spawns `python -m promo_finder run`   ← the pipeline, same code as the CLI
```

Locally the app runs against a local `mongod`. In the cloud it needs an external database,
because Render's filesystem is ephemeral.

**What gets deployed:** `promo_finder/`, `tools/`, `examples/demo_show`, and `mern/`.
`input_pack/`, `outputs/` and `.env` are excluded by `.dockerignore` and never exist in the
image — verified with `docker run … ls /app` (it shows exactly `examples  mern  outputs
promo_finder  tools`). A public URL can therefore never serve Kuku's script or your API key.

What the public copy shows instead is the seeded `demo_show-rules` run from
`examples/demo_show`. The 149-clip run on Kuku's pack stays private because the ranked list
quotes the screenplay — see "What is public, and what is private" in `README.md`.

## Step 1 — MongoDB Atlas (free M0)

1. Sign in at <https://cloud.mongodb.com> (GitHub/Google login is fine).
2. **Build a database** → **M0 / Free** → pick the region closest to your Render region
   (e.g. `AWS · Mumbai ap-south-1` or `Singapore`) → **Create**.
3. **Database Access** → **Add New Database User**
   - Authentication: *Password*
   - Username: `promo`, Password: **Generate** and copy it
   - Role: *Read and write to any database*
4. **Network Access** → **Add IP Address** → **Allow access from anywhere** (`0.0.0.0/0`).
   Render's free tier has no fixed egress IP, so a narrower allowlist breaks the connection
   after a deploy. (Tighten it later if you move to a paid plan with static IPs.)
5. **Clusters → Connect → Drivers** and copy the SRV string, then insert the database name:

   ```
   mongodb+srv://promo:<password>@cluster0.xxxxx.mongodb.net/promo_finder?retryWrites=true&w=majority
   ```

   - URL-encode any `@ : / ?` characters in the password (`@` → `%40`).
   - If your password is generated by Atlas it is usually safe as-is.

That is the only secret the app needs to start. Provider API keys are optional: the deployment
is configured with `PROMO_UI_REQUIRE_KEY=1`, so visitors paste their own key into **New run**
and rules-only runs need no key at all.

## Step 2 — Render

### Option A — blueprint (one click, uses the repo's `render.yaml`)

1. Sign in at <https://render.com> with GitHub and grant access to the repository.
2. **New → Blueprint** → select the repo and branch `main` → **Apply**.
   Render reads `render.yaml` from the repo root, builds `mern/Dockerfile`, and asks for the
   values marked `sync: false` — paste `MONGODB_URI` from step 1.
3. Wait for the first build (~3-5 min: Node deps, Vite build, apt `python3`) → the service
   goes **Live** when `GET /api/health` returns 200.

### Option B — manual web service (if the blueprint flow is unavailable)

1. **New → Web Service** → connect the repo.
2. Language **Docker**, **Dockerfile path** `./mern/Dockerfile`, **Docker context** `.`.
3. Instance type **Free**, health check path `/api/health`.
4. Environment variables:

| Key | Value |
|---|---|
| `MONGODB_URI` | the Atlas SRV string from step 1 |
| `HOST` | `0.0.0.0` |
| `PROMO_SHOW_ROOTS` | `examples` (public demo only) |
| `PROMO_UI_REQUIRE_KEY` | `1` (visitors bring their own provider key) |
| `PROMO_SEED_DEMO` | `1` (seed one rules-only run so the UI is not blank) |
| `LLM_BASE_URL` | `https://platform.qubrid.com/v1` |
| `LLM_MODEL` | `zai-org/GLM-4.7-Flash` |

Do **not** set `PORT` — Render injects its own and the server binds to it.

### First boot

```
MongoDB connected · 0 run(s) ingested: none
Seeded a rules-only run of examples/demo_show as "demo_show-rules" (no API key, no cost)
Promo Finder MERN API on http://0.0.0.0:<port>
```

The demo run means `/` is never empty on a fresh deployment. `PROMO_SEED_DEMO=0` disables it.

| New run → `demo_show` → *rules only* → Start | progress parse → mine → trailers → rank, new run appears |

The two **skipped** checks are the ones needing `input_pack/` (Kuku's script) and
`outputs/full_run/` (the submitted 149 clips). They pass on your machine, never in public —
that is the intended behaviour, not a failure.

Reference numbers when you run it locally against the real run:
`npm run parity` → 6/6 identical to the Python app; `/api/selftest` → 14 pass / 0 fail.

## Keeping a free instance warm

A free Render web service sleeps after **15 minutes without traffic**, and waking it takes
40-50 s — long enough that a reviewer opening your link cold may see nothing and leave.

The free plan allows **750 instance-hours per month**; running 24/7 uses about **730**, so
keeping it awake does not exceed the plan. The sleep is triggered by idleness, not by quota.
Two ways to remove the idleness:

**A. The GitHub Action in this repo** (`.github/workflows/keepalive.yml`)

1. Repo → **Settings → Secrets and variables → Actions → Variables → New repository variable**
2. Name `PROMO_APP_URL`, value `https://promo-finder-mern.onrender.com` (no trailing slash)
3. It runs every 10 minutes (`cron: "*/10 * * * *"`), curls `/api/health`, and fails visibly in
   the Actions tab if the app is down — so it doubles as uptime monitoring. Use **Run workflow**
   to trigger it once immediately.

**B. An external uptime monitor** (no repo changes): UptimeRobot / cron-job.org → new HTTP(S)
monitor → URL `https://<app>/api/health` → interval **5 minutes** → save. The free tiers allow
this and are more punctual than GitHub's scheduler.

**Prove it is warm** — run twice, 20 minutes apart; both should be well under a second:

```bash
curl -s -o /dev/null -w "%{http_code} %{time_total}s
" https://promo-finder-mern.onrender.com/api/health
```

A first request of ~40 s means the instance was asleep; anything under 1 s means warm.

**If a reviewer does land on a cold instance:** open `/verify` first and wait for it to render
(~40 s), then share the link. `/verify` itself performs several round-trips, so once it loads
the app is fully awake.

> Free instances are also restarted on every deploy. After a `git push`, the first request is
> slow again for ~40 s — the keep-alive probe recovers it within 10 minutes.

## Free-tier reality (read before you promise anything)

- **Cold start:** a free web service sleeps after 15 min idle; the next request takes ~30-60 s.
  Open `/verify` a minute before a demo, or upgrade to Starter ($7/mo) to keep it warm.
- **512 MB / 0.1 CPU:** fine for browsing, storyboards and rules-only runs. A 50-episode LLM
  run from the public URL is not advisable — that is what your machine is for.
- **Ephemeral disk:** `/app/outputs` and `/app/uploads` are wiped on every deploy/restart.
  Runs already in MongoDB still list and their storyboards still work while the show scripts
  are in the image (`examples/`); uploads would need to be re-uploaded.
- **One run at a time:** the app enforces a single concurrent pipeline job, same as the Python
  UI — free provider tiers rate-limit (HTTP 429) otherwise.
- Never put `LLM_API_KEY` into a public instance. Keep `PROMO_UI_REQUIRE_KEY=1`, and rotate
  the key you used for the submission run afterwards.

## Updating

```bash
git add -A && git commit -m "…" && git push        # Render redeploys on push to main
```

Rollback: Render → the service → **Deploys** → **Rollback** to a previous build.
Schema changes are safe: ingestion is idempotent and never touches editor reviews.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Deploy fails at health check | `HOST` must be `0.0.0.0`, and don't set `PORT` yourself |
| `MongoServerError: bad auth` | password not URL-encoded, or the DB user was not created in *this* project |
| `MongoDB not reachable` in logs, service still Live | IP allowlist: add `0.0.0.0/0` |
| Blank white page | the client build did not run — check the `client` stage of the build log |
| Every model call fails with `CERTIFICATE_VERIFY_FAILED … unable to get local issuer certificate` | the image is missing `ca-certificates` (Debian slim has none), so Python cannot verify HTTPS. Fixed in `mern/Dockerfile` (`python3 ca-certificates` + `update-ca-certificates`); rebuild. Symptom: ~2.5 min per episode of retries, then a rules-only list |
| `/verify`: "could not start python3" | the image lost `python3`: rebuild from `mern/Dockerfile`, do not use a Node-only runtime |
| `/verify`: cut audit fails "can't open file /app/tools/…" | `tools/` was not copied into the image (fixed in commit `35ac3c8`+, verify your branch) |
| Build is slow / huge context | `.dockerignore` must be at the repo root; without it the build uploads `input_pack/` and `outputs/` |
| A run refuses to start with `cannot reach … from the pipeline` | the new pre-flight probe could not reach the provider from Python's TLS stack (bad URL, DNS, missing CA bundle). Fixed in seconds instead of failing every episode |
| A run lists clips but the storyboard is empty / `clip` returns 400 | the run was ingested on another machine, so its stored `input_dir` is a path that does not exist here. The API falls back to the show folder on this host; re-ingesting (`POST /api/sync`) rewrites the path too |

## Alternatives to Render

- **Railway / Fly.io** — same Dockerfile, same env vars; `fly launch --dockerfile mern/Dockerfile`.
- **Your own VPS** — `docker compose -f mern/docker-compose.yml up -d --build` gives app +
  MongoDB in one command, and output files survive restarts.
- **Hugging Face Spaces (Docker)** — works, but Spaces routes to port **7860**: add
  `ENV PORT=7860` to the Space's Dockerfile copy, and note the free CPU is slower than Render's.
